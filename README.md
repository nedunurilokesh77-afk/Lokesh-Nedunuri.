# Lokesh Nedunuri — Engineering Portfolio

A cinematic personal portfolio for Lokesh Nedunuri, B.Tech Electronics and Communication Engineering student at VIT-AP University. Built with Next.js, React, TypeScript, Three.js, GSAP and Lenis.

## Requirements

- Node.js 20.9+ (Node.js 22 LTS recommended)
- npm
- Git

## Run locally (Windows PowerShell / macOS / Linux)

```bash
npm install
Copy-Item .env.example .env   # Windows PowerShell
# macOS/Linux: cp .env.example .env
```

Edit `.env`:

- Set `NEXT_PUBLIC_SITE_URL` to your deployed website origin when you have one. For local work, use `http://localhost:3000`.
- `DATABASE_URL` is used by the contact form's Prisma/SQLite setup for local development.

Initialize the local database and start the site:

```bash
npx prisma generate
npx prisma db push
npm run dev
```

Open http://localhost:3000.

## Production build

```bash
npm run typecheck
npm run lint
npm run build
npm start
```

The production build uses Next.js standalone output. `scripts/prepare-standalone.mjs` copies static and public assets into the standalone directory on Windows, macOS and Linux.

## Deploy to Vercel

1. Push this repository to GitHub (instructions below).
2. In Vercel, choose **Add New → Project** and import this GitHub repository.
3. Keep the detected Next.js framework settings and build command `npm run build`.
4. Add `NEXT_PUBLIC_SITE_URL` as an environment variable using your real deployed domain, e.g. `https://your-domain.com` (no trailing slash).
5. Deploy. Add your custom domain in Vercel and configure the DNS records Vercel provides.

### Contact form database warning

The included contact API uses Prisma with SQLite for local development. A local SQLite file is not a durable database for serverless production hosting. Before relying on the form in production, migrate the Prisma datasource to a managed persistent database (for example PostgreSQL), configure its connection string and run the production migration. Until then, publish a verified email address in `src/data/portfolio.ts` or keep the form disabled.

Verified GitHub and LinkedIn profile URLs are included in the Person structured data (`sameAs`) automatically when supplied.

## Google Search Console setup

After deployment and domain verification:

1. Open https://search.google.com/search-console and add your domain as a **Domain property**.
2. Verify ownership using the DNS TXT record Google provides.
3. Open **Sitemaps** and submit `https://YOUR-DOMAIN/sitemap.xml`.
4. Use **URL Inspection** to inspect the homepage and `/about`, then request indexing.
5. Check the Pages/Indexing report and Core Web Vitals periodically.
6. Keep the site accessible to crawlers and do not block the site in robots rules.

Also create or update public profiles that genuinely belong to you (GitHub, LinkedIn, university profile if available). Use the same name **Lokesh Nedunuri**, link each profile to your official website, and link back to those profiles from your website. Ask hackathon/team/project pages to credit you with a link when appropriate. Do not create fake profiles, fake awards or spammy backlinks.

## Push to GitHub (Windows PowerShell)

Create an empty repository on https://github.com/new. Do not initialize it with a README, license or .gitignore because this folder already contains those files.

Open PowerShell in this project folder and run:

```powershell
git init
git add .
git status
git commit -m "Build Lokesh Nedunuri portfolio with SEO"
git branch -M main
git remote add origin https://github.com/YOUR-GITHUB-USERNAME/lokesh-nedunuri-portfolio.git
git push -u origin main
```

Replace `YOUR-GITHUB-USERNAME` with your actual GitHub username and use the repository URL GitHub shows you. If Git asks you to sign in, complete the browser authentication.

For later updates:

```powershell
git add .
git commit -m "Update portfolio"
git push
```

## Important

- Never commit `.env`, `.env.local`, API keys, database files, passwords or private keys.
- `.gitignore` excludes environment files, dependencies, build output and local databases.
- GitHub Pages does not run a Next.js server/API route. Use Vercel for this Next.js project, or export a static site only after removing server-dependent features.
